# 第 14 章：第三方整合

---

## 14.1 模組概述

第三方整合模組定義所有外部服務的接入標準、SLA 要求、容錯機制。確保第三方故障不導致平台停機。

**核心職責**: 整合標準、供應商 SLA、Webhook 重試、API 金鑰管理、服務降級

---

## 14.2 整合原則

| 原則 | 說明 |
|------|------|
| 統一適配層 | 所有第三方透過統一 Adapter 接入 |
| 容錯優先 | 第三方故障 ≠ 平台故障 |
| 監控優先 | 每個整合點均有健康檢查與警報 |
| 安全優先 | 加密 API 金鑰、Webhook 簽名驗證 |

---

## 14.3 供應商 SLA

| 服務 | 最低可用率 | P99 回應時間 | 速率限制 |
|------|----------|------------|---------|
| PSP (支付) | 99.5% | < 3 秒 | — |
| KYC 供應商 | 98.0% | < 5 秒 | 100 次/分鐘 |
| 遊戲供應商 | 99.0% | < 3 秒 | 500 次/分鐘 |
| Email 服務 | 99.0% | < 1 秒 | 1,000 次/小時 |
| 分析服務 | 95.0% | 盡力 | 無限制 |

### SLA 管理

- 30 天滾動窗口計算
- 違約時供應商提供月度服務信用
- 低於目標自動升級至供應商經理

### 第三方資料駐留合規

> v2.2 新增 — GAP-5（第三方資料駐留合規）
> ⏳ 待合規團隊 + 法務確認

**問題**: EU 平台使用 US-based PSP/KYC 供應商時，可能違反 GDPR 資料傳輸規則。

| 要求 | 說明 | 狀態 |
|------|------|------|
| 資料駐留 | PII 必須留在資料駐留區域內處理 | ⏳ 待法務確認各區域要求 |
| SCC (標準合約條款) | 跨境資料傳輸須簽署 SCC | ⏳ 待法務準備模板 |
| DPA (資料處理協議) | 所有第三方整合前須簽署 DPA | ⏳ 待合規流程定義 |
| 年度稽核 | 每年審計第三方資料處理實務 | ⏳ 待稽核排程 |
| Schrems II 合規 | 確認 EU→US 資料傳輸符合 Schrems II 判決 | ⏳ 待法務評估 |

### PSP SLA vs 平台 RTO 兼容性

**問題**: PSP SLA 99.5% 允許每月約 22 分鐘停機，但 Ch10 定義支付 RTO < 15 分鐘。

**解決方案 — PSP 降級策略**:

| 階段 | 條件 | 動作 |
|------|------|------|
| 偵測 | 主 PSP 連續 3 次請求失敗或 P99 > 5 秒 | 觸發 Circuit Breaker |
| 切換 | Circuit Breaker OPEN | 自動路由至備用 PSP（< 30 秒） |
| 恢復 | 主 PSP 連續 3 次健康檢查通過 | 逐步切回（25% → 50% → 100%） |

**RTO 計算規則**: 平台 RTO 計算**排除**外部 PSP 不可控停機時間，但平台須在 PSP 停機 30 秒內完成備援切換。

## 14.4 Webhook 重試策略

### 指數退避重試 (6 次)

| 重試次數 | 延遲 | 累計 |
|---------|------|------|
| 1 | 5 秒 | 5 秒 |
| 2 | 10 秒 | 15 秒 |
| 3 | 20 秒 | 35 秒 |
| 4 | 40 秒 | 75 秒 |
| 5 | 80 秒 | 155 秒 |
| 6 | 160 秒 | 315 秒 |

### Webhook 冪等性（接收端）

| 項目 | 規則 |
|------|------|
| Idempotency Key | 每個 webhook 須攜帶唯一 `idempotency_key`（由發送方生成） |
| 去重窗口 | 24 小時（Redis SET + TTL 24h） |
| 重複處理 | 收到重複 `idempotency_key` → 回傳 200 OK + 原始處理結果（不重複執行） |
| 缺少 Key | 回傳 400 Bad Request（PSP / GP 整合強制要求） |
| 簽名驗證 | HMAC-SHA256 簽名驗證 → 失敗則回傳 401 + 記錄告警 |

### 死信佇列 (DLQ)

| 項目 | 規則 |
|------|------|
| 進入條件 | 6 次重試全部失敗 |
| 保留期限 | 7 天 |
| 手動重放 | 支援 |
| 警報 | DLQ 事件 > 100 則觸發 |

## 14.5 API 金鑰管理

| 服務類型 | 輪換週期 | 自動/手動 | 觸發條件 |
|---------|---------|----------|---------|
| PSP API | 90 天 | 自動 | 週期性 + 可疑活動 |
| 內部服務 | 30 天 | 自動 | 週期性 |
| Webhook Secret | 按需 | 手動 | 疑似洩漏 |
| 資料庫密碼 | 180 天 | 自動 | 週期性 |

**安全要求**:
- 所有金鑰存放於加密秘密管理器
- 禁止出現在原始碼、日誌或配置檔中
- RBAC 存取控制
- 所有存取留審計記錄

### Webhook 簽名演算法升級路徑

| 項目 | 規則 |
|------|------|
| 當前演算法 | HMAC-SHA256 |
| 版本協商 | Webhook Header 包含 `X-Signature-Version: v1` |
| 過渡期策略 | 新版發布後 90 天內同時接受 v1 和 v2 簽名 |
| 升級通知 | 提前 60 天通知所有 webhook 消費者 |
| 降級回退 | 若 v2 驗證失敗率 > 1%，自動回退至 v1 |

## 14.6 服務降級與容錯

### 降級優先級

| 服務 | 優先級 | 影響 | 備援方案 |
|------|--------|------|---------|
| PSP | 嚴重 | 無法存提款 | 切換備用 PSP |
| KYC | 重要 | 無法驗證身份 | 人工審核佇列 |
| 遊戲供應商 | 重要 | 特定遊戲不可用 | 維護中通知 |
| Email | 可選 | 通知延遲 | 重試佇列 |
| 分析 | 可選 | 無事件追蹤 | 本地日誌 |

### 恢復偵測

| 項目 | 規則 |
|------|------|
| 健康檢查間隔 | 30 秒 |
| 恢復條件 | 連續 3 次健康檢查通過 (> 95%) |
| 恢復動作 | 自動切回主要服務 |
| 記錄 | 恢復事件記入警報管道 |

## 14.7 監控與警報

### 即時健康儀表板

- 可用率 % (過去 1 小時)
- P99 回應時間
- 錯誤率
- 狀態指示器 (健康/降級/不可用)

### 警報配置

| 警報 | 條件 | 嚴重度 |
|------|------|--------|
| PSP 失敗率 | > 5% / 5 分鐘窗口 | 嚴重 |
| KYC P99 延遲 | > 5 秒 / 10 分鐘 | 警告 |
| Email 發送失敗 | 任何失敗 | 警告 |
| DLQ 累積 | > 100 事件 | 高 |
