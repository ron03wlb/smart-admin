## Business Value

此租戶配置系統提供以下價值：
- **營運自主性（Operational Autonomy）**：讓租戶能夠自主管理站點屬性（域名、貨幣、時區、營運開關、IP 限制、遊戲黑名單），無需平台介入，降低營運負擔並加速配置變更的上線時間
- **零停機配置（Zero-Downtime Configuration）**：支援動態配置變更，在 1 分鐘內傳播到所有節點且無需服務重啟（Section 4.1），消除配置更新的維護窗口
- **市場專屬模板（Market-Specific Templates）**：提供亞洲（VN/TH）、歐洲（EU）和拉丁美洲的預配置模板，包含市場適當的預設值（貨幣、支付方式、KYC 等級、提款限額、語言支援），實現快速租戶入駐與符合地區法規的設定
- **透過審批流程降低風險（Risk Mitigation Through Approval Workflow）**：對高風險操作（IP 限制、域名綁定、維護模式）強制雙重審查批准，同時允許標準操作（站點名稱、限額、遊戲切換）僅需審計記錄，平衡敏捷性與安全性
- **主動健康監控（Proactive Health Monitoring）**：持續配置一致性檢查（30 秒）、域名 DNS 驗證（5 分鐘）、IP 衝突偵測（變更時）和租戶餘額門檻告警（每小時），防止配置漂移與服務降級

## Success Metrics

| 指標 | 目標 | 測量 |
|--------|--------|-------------|
| 配置傳播延遲 | < 1 分鐘 | 從配置儲存到所有節點反映新版本的時間（Section 4.1） |
| 配置一致性率 | 99.9% | 健康檢查顯示所有節點配置版本一致的百分比（Section 6.1） |
| 模板採用率 | ≥ 70% | 使用市場模板 vs 自訂配置的新租戶百分比 |
| 審批流程 SLA（高風險操作） | < 4 小時 | IP/域名/維護變更從提交到核准的中位時間（Section 4.2） |
| 審計追蹤完整性 | 100% | 所有配置變更均記錄 Who/What/When/Why/Approval/Source IP 欄位（Section 4.3） |
| 零停機配置變更 | 100% | 配置更新不觸發服務重啟（Section 4.1） |
| 配置驗證錯誤率 | < 1% | 配置提交未通過業務規則驗證的百分比（Section 7.2） |
| 租戶餘額告警覆蓋率 | 100% | 所有餘額 < $1,000 的租戶接收每小時告警（Section 6.2） |

## 1. 業務概述（Business Overview）

租戶配置系統提供「開箱即用」的站點配置能力，使租戶能夠自主管理其站點屬性。所有配置變更必須動態生效，無需服務重啟。

---

## 2. 核心配置項目（Core Configuration Items）

### 2.1 基本資訊（Basic Information）

| 配置 | 描述 | 範例 |
|--------------|-------------|---------|
| **站點名稱** | 顯示在瀏覽器標題列 | "Casino VN" |
| **主域名** | 主要站點域名 | www.abc.com |
| **API 域名** | 後端 API 域名 | api.abc.com |
| **CDN 域名** | 靜態資源域名 | img.abc.com |
| **基礎貨幣** | 主要營運貨幣 | VND |
| **支援貨幣** | 額外錢包貨幣 | USD, VND, THB |
| **時區** | 營運時區 | Asia/Ho_Chi_Minh |

### 2.2 營運開關（Operational Switches）

| 開關 | 描述 | 影響 |
|--------|-------------|--------|
| **維護模式** | 一鍵全站或前端維護 | 阻止所有玩家存取 |
| **註冊開關** | 暫停新用戶註冊 | 防止新註冊 |
| **存款開關** | 啟用/停用存款 | 控制資金流入 |
| **提款開關** | 啟用/停用提款 | 控制資金流出 |

### 2.3 IP 與地理限制（IP & Geo Restrictions）

| 限制類型 | 描述 | 範例 |
|-----------------|-------------|---------|
| **國家允許清單** | 允許存取的國家（GeoIP） | VN, TH, ID |
| **國家黑名單** | 封鎖存取的國家 | US, UK, FR |
| **辦公室 IP 白名單** | 授權管理後台 IP | 192.168.1.0/24 |

### 2.4 遊戲額度配額（轉帳模式，Game Credit Quota, Transfer Mode）

| 規則 | 描述 |
|------|-------------|
| **預付模式（Pre-paid Model）** | 租戶必須先向平台購買額度，玩家才能遊戲 |
| **低餘額告警（Low Balance Alert）** | 當租戶餘額低於門檻時觸發告警 |
| **自動封鎖（Auto-block）** | 餘額不足時，玩家無法轉入遊戲 |

### 2.5 遊戲管理（Game Management）

| 功能 | 描述 | 粒度 |
|---------|-------------|------------|
| **供應商黑名單** | 封鎖整個遊戲供應商 | 例如，封鎖所有 PG Soft 遊戲 |
| **遊戲黑名單** | 封鎖特定遊戲 | 例如，封鎖「Mahjong Ways 2」 |
| **維護模式** | 租戶級遊戲維護頁面 | 獨立於平台維護 |

## 3. 配置模板（Configuration Templates）

### 3.1 市場模板（Market Templates）

| 模板 | 預設貨幣 | 支付方式 | KYC 等級 | 提款限額 |
|----------|-----------------|----------------|-----------|-----------------|
| **亞洲（VN）** | VND | VietQR, MoMo, ZaloPay | BASIC | 50M VND/天 |
| **亞洲（TH）** | THB | PromptPay, TrueMoney | BASIC | 200k THB/天 |
| **歐洲（EU）** | EUR | SEPA, Trustly | FULL (GDPR) | 10k EUR/天 |
| **拉丁美洲** | BRL/MXN | PIX, Mercado Pago | BASIC | 50k BRL/天 |

### 3.2 模板自動配置（Template Auto-Configuration）

使用模板建立新租戶時，以下項目自動配置：

| 項目 | 描述 |
|------|-------------|
| 貨幣與時區 | 基於市場區域 |
| 支付方式 | 該市場預選 |
| 遊戲供應商 | 該區域熱門供應商 |
| KYC 要求 | 基於監管環境 |
| 自動核准門檻 | 提款自動核准限額 |
| 語言支援 | 主要 + 次要語言 |

## 4. 動態配置與審批（Dynamic Configuration & Approval）

### 4.1 動態配置原則（Dynamic Configuration Principles）

| 原則 | 要求 |
|-----------|-------------|
| **即時生效** | 變更必須在 1 分鐘內傳播到所有節點 |
| **零停機** | 配置變更絕不能導致服務重啟 |
| **版本追蹤** | 每次變更產生新版本 |

### 4.2 審批需求（Approval Requirements）

#### 高風險操作（雙重審查必須，Dual Review Required）

| 操作 | 風險 | 審批流程 |
|-----------|------|--------------|
| **修改 IP 限制** | 封鎖合法流量或開放後門風險 | 租戶管理員提交 > 平台營運審查 > 生效 |
| **修改域名綁定** | 域名劫持風險 | 租戶管理員提交 > 平台營運審查 > 生效 |
| **停用維護模式** | 過早恢復風險 | 租戶管理員提交 > 平台營運審查 > 生效 |

#### 標準操作（僅需審計追蹤，Audit Trail Only）

| 操作 | 要求 |
|-----------|-------------|
| 修改站點名稱/Logo | 無需審批，但必須記錄審計日誌 |
| 調整存款/提款限額 | 記錄審計日誌（舊值/新值） |
| 切換遊戲供應商狀態 | 記錄審計日誌 |

### 4.3 審計日誌需求（Audit Log Requirements）

每次配置變更必須記錄：

| 欄位 | 描述 |
|-------|-------------|
| **Who（誰）** | 用戶 ID 與角色 |
| **What（什麼）** | 變更欄位與舊/新值 |
| **When（何時）** | 變更時間戳 |
| **Why（為什麼）** | 變更原因 |
| **Approval（審批）** | 審批狀態與審批人（如適用） |
| **Source IP** | 請求者 IP 位址 |

## 5. 配置優先級規則（Configuration Priority Rules）

配置值按以下順序解析（最高到最低優先級）：

| 優先級 | 來源 | 描述 | 範例 |
|----------|--------|-------------|---------|
| 1（最高） | **運行時覆蓋（Runtime Override）** | 營運團隊即時調整 | 促銷期間：最低存款 = $20 |
| 2 | **租戶配置（Tenant Config）** | 租戶自訂設定 | VIP 租戶：最低存款 = $1 |
| 3 | **模板配置（Template Config）** | 市場模板預設 | 亞洲模板：最低存款 = $5 |
| 4（最低） | **系統預設（System Default）** | 平台全域預設 | 系統預設：最低存款 = $10 |

## 6. 監控與健康檢查需求（Monitoring & Health Check Requirements）

### 6.1 配置健康檢查（Configuration Health Checks）

| 檢查項目 | 頻率 | 失敗時動作 |
|-----------|-----------|-------------------|
| 所有閘道節點配置版本一致 | 每 30 秒 | 告警營運團隊 |
| 域名 DNS 解析有效 | 每 5 分鐘 | 告警租戶管理員 |
| 無 IP 白名單/黑名單衝突 | 每次變更時 | 封鎖該變更 |
| 租戶餘額高於最低門檻 | 每小時 | 告警租戶 + 平台 |

### 6.2 告警規則（Alert Rules）

| 條件 | 嚴重性 | 通知 |
|-----------|----------|-------------|
| 配置同步失敗（版本不一致 > 1 分鐘） | 警告 | 營運團隊 |
| 租戶餘額低於門檻（< $1,000） | 警告 | 租戶 + 平台 |
| 維護模式在計畫外窗口啟動 | 嚴重 | 所有利害關係人 |
| 域名綁定未經審批變更 | 嚴重 | 安全團隊 |

## 7. 驗證規則（Validation Rules）

### 7.1 輸入驗證（Input Validation）

| 欄位 | 驗證規則 |
|-------|----------------|
| 域名 | 有效域名格式（正則表達式檢查） |
| IP 位址 | 有效 IPv4 或 IPv6 格式 |
| 貨幣代碼 | ISO 4217 標準 |
| 時區 | IANA 時區資料庫 |
| 金額限額 | 配置的最小/最大範圍內的正數 |
| 國家代碼 | ISO 3166-1 alpha-2 |

### 7.2 業務規則驗證（Business Rule Validation）

| 規則 | 描述 |
|------|-------------|
| 不能同時在白名單與黑名單 | IP/國家不能同時出現在兩個清單中 |
| 提款限額 >= 最低提款額 | 提款限額至少為最低金額 |
| 至少一個支付方式啟用 | 不能停用所有支付方式 |
| 至少一個語言配置 | 必須至少有一個啟用語言 |
