# 第 8 章：代理營運

---

## 8.1 模組概述

代理營運模組負責管理代理層級網路、信用額度、佣金結算，以及代理自助門戶。此模組是 B2B 端的核心收入分配機制，須支援最多 10 層代理層級與多種佣金模式。

**核心職責**: 信用網路、佣金模型、結算週期、代理層級管理、代理門戶

---

## 8.2 代理層級結構

### 層級規則

| 項目 | 規則 |
|------|------|
| 最大層級 | 10 層 |
| 信用額度分配 | 僅限由上而下 (上級 → 下級) |
| 每層額度 | 不可超過上級分配的額度 |
| 新代理建立 | 須上級代理或租戶管理員核准 |

### 代理角色

| 角色 | 權限 | 說明 |
|------|------|------|
| 總代理 | 管理下線代理、分配額度、查看全線報表 | 租戶直屬 |
| 中間代理 | 管理下線、向下分配額度 | 可多層 |
| 末端代理 | 管理玩家、不可再分 | 直接面對玩家 |

---

## 8.3 信用網路

### 雙錢包模型

每個代理玩家擁有兩個錢包:

| 錢包 | 說明 | 提款規則 |
|------|------|---------|
| **CASH** | 玩家自有現金 | 依 KYC 限額提款 |
| **CREDIT** | 代理授信額度 | 不可提款，僅用於投注 |

### 信用額度管理

| 項目 | 規則 |
|------|------|
| 初始額度 | 代理設定 (預設 0) |
| 額度調整 | 代理可隨時調高/調低，不可低於已使用額度 |
| 額度上限 | 受上級代理分配的總額限制 |
| 已使用額度 | 信用額度 - 可用額度 |
| **自我排除檢查** | 代理授信或調整額度前，須檢查玩家是否處於自我排除狀態（見 Ch15）。已排除玩家**禁止**接受任何信用額度操作 |
| **排除廣播** | 玩家觸發自我排除時，系統自動凍結該玩家的 CREDIT 錢包，並通知其代理 |

### 風險閾值

| 使用率 | 風險等級 | 處置 |
|--------|---------|------|
| ≤ 80% | 正常 | — |
| 81–90% | 警告 | 通知代理 |
| 91–100% | 高風險 | 限制新投注，通知上級 |
| > 100% | 嚴重 | 凍結帳戶，強制結算 |

## 8.4 佣金模型

### 佣金類型

| 模型 | 計算方式 | 適用場景 |
|------|---------|---------|
| **收益分成** | 淨盈虧 × 分成比例 (階梯式) | 最常見 |
| **流水返佣** | 有效投注額 × 返佣率 (按遊戲類型) | 大流水代理 |
| **CPA** | 每位新註冊/首存玩家固定金額 | 推廣期 |
| **混合模式** | 收益分成 + 流水返佣 | 大型代理 |

### 收益分成階梯

| 月淨盈利 | 分成比例 | 說明 |
|---------|---------|------|
| < $10,000 | 30% | 基礎 |
| $10,000–$50,000 | 35% | — |
| $50,000–$200,000 | 40% | — |
| > $200,000 | 45% | 頂級代理 |

### 流水返佣率 (按遊戲類型)

| 遊戲類型 | 返佣率 |
|---------|--------|
| Slots | 0.5% |
| Live Casino | 0.3% |
| Sports | 0.4% |
| Table Games | 0.2% |

### 佔成模式 (Position Holding)

| 項目 | 規則 |
|------|------|
| 概念 | 代理可宣告承擔風險的百分比 |
| 盈利分配 | 玩家輸 → 代理獲得宣告比例的利潤 |
| 虧損承擔 | 玩家贏 → 代理承擔宣告比例的虧損 |
| 正規化 | 若下線佔成 > 100%，按比例縮減 |

## 8.5 結算規則

### 結算週期

| 週期 | 適用場景 | 結算日 |
|------|---------|--------|
| 每週 | 一般代理 | 每週一 |
| 每月 | 大型代理 / 特殊合約 | 每月 1 日 |

### 結算流程

| 階段 | 說明 | 負責人 |
|------|------|--------|
| 1. 系統計算 | 自動計算佣金 / 佔成盈虧 | 系統 |
| 2. 財務審核 | 核實計算結果 | 財務 |
| 3. 主管核准 | 大額結算需主管審批 | 主管 |
| 4. 自動發放 | 轉入代理錢包 | 系統 |

### 負結轉規則

| 規則 | 說明 |
|------|------|
| 負餘額結轉 | 代理本期虧損結轉至下期 |
| 閾值重置 | 累計虧損達 -$1,000,000 時可申請重置 |
| 年度重置 | 年底可選擇性重置 (須審批) |
| **多幣種結轉** | 負結轉統一以代理的結算幣種計算。月結時按結算日即時匯率折算 |
| **FX 風險歸屬** | 代理承擔投注日至結算日之間的匯率波動風險。詳見 Ch2 §2.13 FX 波動風險分攤矩陣（SSOT） |
| **與信用額度的關係** | 信用額度為硬上限，負結轉**不影響**信用額度計算。公式: `可用信用 = 信用額度 - 已使用額度`（負結轉不計入已使用額度，因它是佣金層面的虧損，非信用層面的債務） |

### 信用額度併發控制

| 項目 | 規則 |
|------|------|
| 鎖定策略 | 樂觀鎖（version 欄位）— 適用於中低併發場景 |
| 高併發場景 | 同一玩家同時多筆投注時，序列化額度扣減（與 Ch2 §2.7 情境 B 一致） |
| 超額處理 | 併發導致瞬時超額 → 拒絕後續投注，不回滾已成功的投注 |
| 額度刷新 | 投注結算（Win/Loss）後即時更新可用額度 |

## 8.6 代理層級變更時資料遷移

| 場景 | 遷移規則 |
|------|---------|
| 代理上移（升為上級） | 下線玩家與子代理跟隨遷移 |
| 代理下移（降為下級） | 下線玩家保留，子代理需重新分配 |
| 代理轉移（更換上級） | 下線玩家跟隨，佣金歷史保留在原代理報表 |
| 結算中轉移 | 當期結算完成後才生效（不可在結算週期中途轉移） |
| 佣金歷史 | 永久保留在原代理下，不隨轉移而遷移 |
| 信用額度 | 轉移後信用額度由新上級重新分配 |

## 8.8 代理風控

### 偵測項目

| 風險 | 偵測方式 | 處置 |
|------|---------|------|
| 同 IP 玩家濫用 | IP 關聯分析 | 調查 + 可能凍結 |
| 佔成套利 | 上下線佔成不合理 | 人工審核 |
| 多帳戶連結 | 設備/支付方式關聯 | 與 Ch6 風控協同 |
| 異常佣金 | 佣金突增偏離歷史 | FLAG + 調查 |

## 8.11 代理帳戶安全需求

> v2.2 新增 — GAP-2（代理帳戶 MFA 與 IP 安全需求）

**原則**: 代理處理大額資金（信用額度分配、結算審批），安全等級應等同於 Ch7 管理員帳戶。

### 認證要求

| 項目 | 規則 |
|------|------|
| MFA | **強制**，所有代理帳戶須啟用 TOTP 或硬體金鑰 |
| 首次登入 | 強制設定 MFA，未設定前禁止任何操作 |
| MFA 備援 | 提供一次性恢復碼（10 組），須安全保存 |

### IP 白名單

| 項目 | 規則 |
|------|------|
| IP 限制 | 代理僅可從預先註冊的 IP 登入 |
| 最大 IP 數 | 每帳戶 ≤ 5 個 |
| IP 變更 | 須上級代理或租戶管理員核准 |
| 非白名單 IP 登入 | 拒絕 + 通知帳戶持有人及上級代理 |

### Session 管理

| 項目 | 規則 |
|------|------|
| 閒置超時 | 30 分鐘無操作 → 自動登出 |
| 同時登入 | 同一帳戶僅允許 1 個活躍 Session |
| 重複登入 | 新 Session 踢掉舊 Session + 通知 |

### 登入失敗保護

| 條件 | 處理 |
|------|------|
| 連續 5 次失敗 | 帳戶鎖定 15 分鐘 |
| 連續 10 次失敗 | 帳戶鎖定 1 小時 + 通知上級代理 |
| 連續 20 次失敗 | 帳戶永久鎖定 + 須人工解鎖 |

### 敏感操作再認證

以下操作須重新輸入 MFA 驗證碼：

| 操作 | 再認證要求 |
|------|----------|
| 信用額度調整 | MFA |
| 結算審批 | MFA |
| 下線代理建立/停用 | MFA |
| 佣金模型變更 | MFA + 上級核准 |
| 代理層級變更 | MFA + 租戶管理員核准 |

### 審計日誌

所有代理操作須記錄以下資訊：
- 操作類型、目標帳戶/金額
- 執行者 IP、設備指紋、時間戳
- MFA 驗證結果
- 保留期限: ≥ 3 年（合規要求）

## 8.12 大額結算審批門檻

> v2.2 新增 — GAP-3（大額結算審批門檻量化）
> ✅ **已決策 (2026-03-25)** — Ron 確認預設值，所有門檻透過 DB 配置，不硬編碼。
> 📎 配置 param_key: `ch8.settlement.auto_max`, `ch8.settlement.manager_approval_max`, `ch8.settlement.cfo_approval_max`, `ch8.settlement.monthly_escalation`（見 [可配置參數註冊表](./PRD_Configurable_Parameters_Registry_可配置參數註冊表.md)）

**問題**: §8.5 要求「大額結算需主管審批」但未量化「大額」門檻。

### 審批層級

| 單筆結算金額 | 審批層級 | SLA |
|------------|---------|-----|
| < $10,000 | 自動發放（系統計算 + 財務審核通過後） | 即時 |
| $10,000 – $49,999 | Manager 審批 | 4 小時 |
| $50,000 – $99,999 | CFO 審批 | 24 小時 |
| ≥ $100,000 | CFO + CEO 雙重審批 | 48 小時 |

### 累計監控

| 指標 | 閾值 | 處理 |
|------|------|------|
| 單一代理月度累計結算 | ≥ $500,000 | 觸發升級審查 |
| 單一代理單週結算增長 | > 200% (相比前 4 週均值) | FLAG + 人工審核 |
| 新代理首月結算 | ≥ $50,000 | 自動 FLAG |

### 配置化

- 所有門檻值可按品牌/管轄區配置
- 門檻調整須 Maker-Checker 審批
- 審計記錄保留所有門檻變更歷史
