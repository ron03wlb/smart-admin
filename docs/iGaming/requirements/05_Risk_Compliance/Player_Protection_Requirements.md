# 玩家保護需求（Player Protection Requirements）

> **規範來源**: [15-07_Player_Protection_API.md](../../source-archive/15_Responsible_Gambling/15-07_Player_Protection_API.md)

> **相關架構**: [Player_Protection_API.md](../../architecture/05_Risk_Engine/Player_Protection_API.md)

---

## 1. 概述

玩家保護模塊提供一套統一的責任博彩工具，使玩家能夠管理自己的賭博活動。這些工具在多個監管框架（UKGC、MGA、Brazil SPA）下是強制性的，並作為平台防止玩家傷害的主要機制。

---

## 成功指標

| 指標 | 目標 | 測量方式 |
|--------|--------|-------------|
| 玩家保護工具採用率 | ≥40% 活躍玩家 | 至少設置一項保護限額（存款/損失/會話）的玩家百分比 |
| 自我排除有效性 | 100% | 在排除期間成功阻止被排除玩家賭博的百分比 |
| 存款限額合規性 | 100% | 根據活躍存款限額正確執行的存款百分比（0 次限額突破） |
| 損失限額執行準確性 | 100% | 達到損失限額時正確阻止的投注百分比 |
| 現實檢查參與度 | ≥70% | 玩家在 2 分鐘內確認現實檢查提示的百分比 |
| Gamstop 同步成功率（UKGC） | ≥99.9% | 成功完成的 Gamstop 檢查和同步操作百分比 |
| Gamstop 匹配偵測 | 100% | 在註冊時正確識別並阻止 Gamstop 註冊玩家的百分比 |
| 限額層級驗證 | 100% | 正確驗證層級規則（每日 ≤ 每週 ≤ 每月）的限額更改百分比 |
| 保護報告及時性 | 100% 準時 | 在報告期結束後 24 小時內生成的合規報告百分比 |
| 冷靜期執行 | ≥24 小時 | 所有存款/損失限額增加生效前應用的最小延遲 |

## 2. 業務目標

| 目標 | 描述 | 優先級 |
|-----------|-------------|----------|
| 監管合規（Regulatory Compliance） | 滿足所有持牌司法管轄區的責任博彩要求 | P0 |
| 玩家賦權（Player Empowerment） | 允許玩家設置和管理自己的保護限額 | P0 |
| 傷害預防（Harm Prevention） | 主動偵測並干預問題賭博行為 | P0 |
| 審計準備（Audit Readiness） | 維護所有保護行動的完整審計追蹤以供監管報告 | P1 |
| 運營商干預（Operator Intervention） | 使運營商能夠在需要時排除玩家 | P1 |

## 3. 面向玩家的保護工具

### 3.1 自我排除（Self-Exclusion）

玩家必須能夠自願在定義的期間內排除自己參與所有賭博活動。

| 需求 | 詳情 |
|-------------|---------|
| 持續時間選項 | 24 小時、7 天、30 天、6 個月、1 年、5 年、永久 |
| 啟用 | 玩家請求後立即啟用；無需運營商批准 |
| 範圍 | 平台上的所有賭博活動（所有遊戲類型） |
| 撤銷 | 玩家僅可在排除期結束後請求撤銷；永久排除無法撤銷 |
| 確認 | 玩家必須在啟用前確認理解 |
| Gamstop 同步（UKGC） | 自我排除必須與英國持牌運營的 Gamstop 同步 |

### 3.2 冷靜期（Cooling-Off Period）

為希望短暫休息的玩家提供的輕量級自我排除替代方案。

| 需求 | 詳情 |
|-------------|---------|
| 持續時間選項 | 可配置（例如 1 天、3 天、7 天） |
| 啟用 | 玩家請求後立即啟用 |
| 範圍 | 所有賭博活動 |
| 自動到期 | 冷靜期在計劃時間自動結束 |
| 重疊規則 | 自我排除活躍時無法啟用冷靜期 |

### 3.3 存款限額（Deposit Limits）

玩家必須能夠設置每日、每週和每月期間的最大存款金額。

| 需求 | 詳情 |
|-------------|---------|
| 期間 | 每日、每週、每月 |
| 層級規則 | 每日限額不得超過每週限額；每週限額不得超過每月限額 |
| 減少 | 立即生效 |
| 增加 | 在生效前需經過強制冷靜期（最少 24 小時） |
| 待處理更改 | 玩家必須能夠查看和取消待處理的限額增加 |
| 重置時間 | 限額在各自期間開始時重置（每日為 UTC 午夜、每週為週一、每月為 1 日） |

### 3.4 損失限額（Loss Limits）

玩家必須能夠設置可配置期間的最大淨損失金額。

| 需求 | 詳情 |
|-------------|---------|
| 期間 | 每日、每週、每月（每月為可選） |
| 計算 | 淨損失 = 期間內總投注 - 總贏獎 |
| 減少 | 立即生效 |
| 增加 | 遵循與存款限額相同的冷靜規則 |
| 執行 | 達到損失限額時，必須阻止所有進一步投注，直到期間重置 |

### 3.5 會話限額（Session Limits）

玩家必須能夠控制會話持續時間並接收定期提醒。

| 需求 | 詳情 |
|-------------|---------|
| 持續時間限額 | 最大會話長度（分鐘）（玩家可配置） |
| 閒置超時 | 不活動一段時間後自動終止會話 |
| 現實檢查（Reality Checks） | 定期通知顯示會話持續時間、淨結果和繼續或退出選項 |
| 現實檢查間隔 | 可配置（默認: 30 分鐘） |

---

## 4. 限額使用可見性

玩家必須實時查看其當前限額使用情況。

| 數據點 | 詳情 |
|------------|---------|
| 當前使用 | 當前期間內使用的金額 |
| 剩餘金額 | 限額與使用之間的差額 |
| 使用百分比 | 已消耗限額的百分比 |
| 重置時間 | 當前期間結束且使用重置的時間 |
| 會話持續時間 | 當前會話長度相對於會話限額 |
| 下次現實檢查 | 下次現實檢查通知的計劃時間 |

---

## 5. 活動歷史

玩家必須能夠查看其完整的保護活動歷史。

| 需求 | 詳情 |
|-------------|---------|
| 記錄類型 | 排除事件、限額更改、冷靜期、現實檢查響應 |
| 日期過濾 | 按開始日期、結束日期過濾 |
| 類型過濾 | 按活動類型過濾 |
| 分頁 | 標準分頁訪問 |
| 保留 | 最少 5 年（監管要求） |

---

## 6. 運營商保護工具

### 6.1 運營商發起的排除（Operator-Initiated Exclusion）

運營商必須能夠在識別出問題賭博指標時排除玩家。

| 需求 | 詳情 |
|-------------|---------|
| 權限 | 具有適當權限的授權員工 |
| 持續時間選項 | 與玩家自我排除相同 |
| 原因記錄 | 審計追蹤的強制原因字段 |
| 玩家通知 | 向受影響玩家發送可選通知 |
| 審計追蹤 | 完整記錄誰排除了誰、何時以及原因 |

### 6.2 排除管理（Exclusion Management）

運營商必須能夠查看和管理所有玩家排除。

| 需求 | 詳情 |
|-------------|---------|
| 狀態過濾 | 活躍、已完成、待撤銷 |
| 類型過濾 | 自我排除、運營商發起、Gamstop |
| 玩家詳情 | 掩碼的個人數據，授權員工可查看完整詳情 |
| Gamstop 同步狀態 | 排除是否已與 Gamstop 同步 |

### 6.3 Gamstop 整合（UKGC 要求）

對於英國持牌運營，平台必須與 Gamstop 國家自我排除計劃整合。

| 需求 | 詳情 |
|-------------|---------|
| 註冊檢查 | 所有新的英國玩家註冊必須檢查 Gamstop |
| 定期同步 | 定期同步以偵測新的 Gamstop 排除 |
| 所需數據 | 名、姓、出生日期、郵政編碼 |
| 失敗處理 | Gamstop 同步失敗必須記錄、警報並重試 |

## 7. 合規報告

### 7.1 報告類型

| 報告 | 頻率 | 內容 |
|--------|-----------|---------|
| 自我排除摘要 | 每月、每季、每年 | 新、活躍、已完成、已撤銷排除 |
| 存款限額摘要 | 每月 | 有限額的玩家、限額突破、平均限額值 |
| 損失限額摘要 | 每月 | 有限額的玩家、限額突破 |
| 現實檢查摘要 | 每月 | 總檢查次數、繼續率、平均響應時間 |
| Gamstop 同步報告 | 每月 | 執行的檢查、發現的匹配、同步失敗 |

### 7.2 報告要求

| 需求 | 詳情 |
|-------------|---------|
| 匯出格式 | JSON、CSV、PDF |
| 下載 | 報告必須通過安全連結可下載 |
| 保留 | 報告必須按每個司法管轄區要求的期間保留 |
| 及時性 | 報告必須在報告期結束後 24 小時內生成 |

## 8. 錯誤場景

| 錯誤代碼 | 業務場景 | 預期行為 |
|------------|-------------------|-------------------|
| RG_001 | 玩家在排除期間嘗試賭博 | 阻止活動，顯示排除結束日期 |
| RG_002 | 玩家在冷靜期期間嘗試賭博 | 阻止活動，顯示冷靜期結束日期 |
| RG_003 | 存款超過當前存款限額 | 阻止存款，顯示剩餘額度 |
| RG_004 | 投注將超過損失限額 | 阻止投注，顯示剩餘損失額度 |
| RG_005 | 玩家請求撤銷永久排除 | 拒絕請求，解釋永久性質 |
| RG_006 | 玩家在排除期結束前請求撤銷 | 拒絕請求，顯示剩餘排除時間 |
| RG_007 | 玩家嘗試取消不存在的待處理限額更改 | 通知玩家不存在待處理更改 |
| RG_008 | 玩家在強制休息期間嘗試賭博 | 阻止活動，顯示休息結束時間 |
| RG_009 | Gamstop 同步失敗 | 記錄失敗，警報運營，自動重試 |
| RG_010 | 無效限額層級（例如每日限額超過每週） | 拒絕更改，解釋層級規則 |

## 9. 限額更改政策

### 9.1 立即 vs 延遲更改

| 更改類型 | 生效時間 | 理由 |
|-------------|-----------------|-----------|
| 減少任何限額 | 立即 | 保護玩家；無理由延遲 |
| 增加任何限額 | 強制冷靜期後（最少 24 小時） | 防止賭博會話期間衝動增加限額 |
| 設置新限額（從無） | 立即 | 新保護措施有益於玩家 |
| 完全移除限額 | 強制冷靜期後（最少 24 小時） | 視為增加（移除保護） |

### 9.2 待處理更改規則

- 玩家可在生效前隨時取消待處理的增加
- 每種限額類型一次只允許一個待處理更改
- 新的待處理更改替換同一限額類型的任何現有待處理更改

| 指標 | 目標 | 測量方式 |
|--------|--------|-------------|
| 自我排除啟用率 | 100% 立即啟用 | 從玩家請求到活躍排除狀態的時間 |
| 限額更改合規性 | 100% 遵守冷靜規則 | 限額增加 24 小時延遲的審計追蹤驗證 |
| Gamstop 同步成功率 | ≥99.9% | 成功檢查 Gamstop 的英國註冊百分比 |
| 現實檢查傳遞率 | 配置間隔 100% | 玩家在計劃時間收到現實檢查（默認 30 分鐘） |
| 審計追蹤完整性 | 100% 保護事件已記錄 | 所有排除、限額更改和冷靜期事件都有審計記錄 |
| 報告生成及時性 | 期間結束後 24 小時內 | 自我排除、存款限額和現實檢查報告準時生成 |
| Gamstop 同步重試成功 | 100% 最終一致性 | 所有同步失敗被記錄、警報並成功重試 |
