## 2. Scope Boundary

### 2.1 In Scope

- 四層租戶層級管理 (Platform / Brand / Tenant / Agent)
- RBAC 權限矩陣與模擬操作 (Impersonation)
- 數據 100% 隔離策略
- 白標客製化 (White-label)
- 租戶計費模式 (3 種) + 逾期處理
- 管理員 MFA 要求
- 品牌級 SSO (錢包隔離不受影響)
- 租戶遷移 + GDPR 數據可攜性
- 多管轄區合規矩陣 (**本 split 為 SSOT 持有者**)
- 代理層級網路 (最多 10 層)
- 代理雙錢包模型 (CASH + CREDIT)
- 信用額度管理 + 風險閾值
- 4 種佣金模型 + 佔成 (Position Holding)
- 結算週期 + 負結轉規則
- 大額結算分級審批
- 代理自助門戶
- 代理帳戶安全 (MFA + IP 白名單)
- 信用額度併發控制 (樂觀鎖)
- 代理層級變更資料遷移

## 3. Functional Requirements — 治理 (Ch7)

### FR-GOV-01: 四層租戶層級

**來源**: Ch7 §7.2

```
Platform (Super Admin)
  └── Brand (Brand Admin) — 集團層級
        └── Tenant (Tenant Admin) — 獨立站點
              └── Agent — 代理 (詳見 §4)
```

| 層級 | 數據範圍 | 核心權限 |
|------|---------|---------|
| Platform | 全局所有數據 | 建立品牌、全局風控、GP 緊急開關 |
| Brand | 品牌內所有租戶 | 建立/管理租戶、品牌預算、共享黑名單 |
| Tenant | 僅本租戶 | 站點營運、玩家管理、活動配置 |
| Agent | 僅自己的下線 | 下線玩家管理、佣金查詢 |

**驗收條件**:
- 層級建立流程完整 (Platform → Brand → Tenant 逐級)
- 每層角色僅能存取其數據範圍內的資源
- 層級關係不可跨越 (Tenant 不可直屬 Platform，須經 Brand)

### FR-GOV-02: RBAC 權限矩陣

**來源**: Ch7 §7.2

| 操作 | Super Admin | Brand Admin | Tenant Admin | Agent |
|------|:-----------:|:-----------:|:------------:|:-----:|
| 建立品牌 | YES | -- | -- | -- |
| 建立租戶 | YES | YES | -- | -- |
| 全局遊戲開關 | YES | -- | -- | -- |
| 品牌預算調整 | YES | YES | -- | -- |
| 玩家管理 | YES | YES | YES | -- |
| 查看佣金報表 | YES | YES | YES | YES |
| 風控規則配置 | YES | YES (品牌級) | YES (租戶級) | -- |

**擴展要求**:
- 權限須為細粒度 (resource + action)，非粗粒度角色開關
- 支援自訂角色 (Custom Role)，由各層級管理員建立
- 權限變更即時生效 + 審計記錄

### FR-GOV-03: 模擬操作 (Impersonation)

**來源**: Ch7 §7.2

| 規則 | 說明 |
|------|------|
| Super Admin | 可模擬任何 Brand / Tenant / Agent |
| Brand Admin | 可模擬旗下 Tenant / Agent |
| 視覺指示器 | 模擬期間全程顯示 banner (操作者身份 + 被模擬身份) |
| 審計記錄 | 每筆模擬操作完整記錄 (who + as_who + when + what) |
| 權限上限 | 模擬操作不可超越被模擬角色的原始權限 |

### FR-GOV-04: 數據隔離

**來源**: Ch7 §7.3

| 規則 | 要求 |
|------|------|
| 租戶隔離 | 所有查詢場景零跨租戶資料洩漏 |
| 品牌隔離 | Brand A 與 Brand B 之間零訪問 |
| 效能開銷 | 多租戶隔離額外負擔 **< 5%** |
| 跨租戶查詢 | 僅白名單場景 (品牌彙總報表、全局管理、租戶遷移) |
| 禁止回傳 | PII (Email/手機/證件)、錢包餘額、KYC 文件、支付憑證 |
| 審計 | 所有跨租戶查詢記錄操作者、時間、範圍、回傳數據量 |

**共享數據規則**:

| 數據類型 | 共享範圍 | 管理者 |
|---------|---------|--------|
| 玩家黑名單 | 品牌級 (可選) | Brand Admin |
| GP 列表 | 全局 | Super Admin |
| 支付供應商 | 租戶獨立 (獨立商戶 ID) | Tenant Admin |
| 風控規則 | 階層式 (全局預設 + 租戶覆蓋) | 各層級 |

### FR-GOV-05: 白標客製化

**來源**: Ch7 §7.4

| 項目 | 說明 | 必要性 |
|------|------|--------|
| 網域 | 獨立 FQDN + SSL 證書 | 必要 |
| 視覺識別 | Logo (多尺寸)、色彩方案、頁腳文字 | 必要 |
| Email 模板 | 品牌化交易通知，獨立寄件地址 | 必要 |
| SMS Sender ID | 本地化發送者標識 | 建議 |
| 幣種設定 | 主要幣種與匯率 | 必要 |
| 語言支援 | 多語言介面 | 建議 |

### FR-GOV-06: 租戶計費

**來源**: Ch7 §7.5

**三種模式**:

| 模式 | 計算方式 | 適用場景 |
|------|---------|---------|
| 固定月費 | 定額 (如 $1,000/月) | 小型站點 |
| 收益分成 | 有效流水 2-5% | 大型站點 |
| 混合模式 | 底薪 + 分成 (如 $500/月 + 1%) | 平衡風險 |

**帳單週期**: 每月 1 日 / 寬限期 7 天 / 自動續約預設啟用 / PDF (含 VAT)

**逾期處理階梯**:

| 逾期天數 | 處置 |
|---------|------|
| 0-7 天 | 每日警告 Email |
| 8-14 天 | 帳戶標記「高風險」 |
| 15-30 天 | 停止新玩家註冊 |
| 31+ 天 | 全面暫停服務 |

### FR-GOV-07: MFA 要求

**來源**: Ch7 §7.6

**強制 MFA 角色**: Super Admin / 財務人員 / 風控人員 / DB Admin / DevOps

**MFA 方式** (優先級):
1. TOTP (Google Authenticator 等) — 主要
2. 備用碼 (一次性) — 備援
3. SMS / Email OTP — 設備遺失恢復

**設備遺失 SLA**: 24-48 小時恢復，須上級主管核准

### FR-GOV-08: 品牌級 SSO

**來源**: Ch7 §7.7

| 模式 | 說明 |
|------|------|
| 完全隔離 | 每個租戶獨立帳戶 |
| 品牌 SSO | 同品牌下共享登入 |
| 聯合登入 | 第三方 IdP (SAML/OIDC) |

**不可妥協規則**: 無論 SSO 模式如何，**錢包永遠按租戶隔離**。

### FR-GOV-09: 租戶遷移 + GDPR 數據可攜性

**來源**: Ch7 §7.8

**遷移檢查表**:
- [ ] 玩家數據完整性驗證
- [ ] 交易歷史完整
- [ ] 錢包餘額對帳
- [ ] 待處理提款已完成
- [ ] 審計記錄保留
- [ ] 監管通知已發送 (如需要)

**GDPR 數據可攜** (Art 29): 玩家註冊數據、交易歷史、遊戲紀錄、通訊記錄、行銷同意記錄。格式: JSON 或 CSV (含 Schema 說明)。

### FR-GOV-10: 多管轄區合規矩陣 (SSOT)

**來源**: Ch7 §7.9 — **本 split 為此矩陣的 SSOT 持有者，其他域引用此處。**

| 管轄區 | 牌照 | 關鍵要求 |
|--------|------|---------|
| 馬爾他 (MGA) | Class 1-4 | 10 年牌照、EU AML 5 合規、玩家資金隔離 |
| 英國 (UKGC) | Remote Operating Licence | 最嚴格、GAMSTOP 強制、可負擔性評估 |
| 庫拉索 | Master Licence | 加密貨幣友好、較寬鬆監管 |
| 菲律賓 (PAGCOR) | POGO Licence | 本地伺服器要求、AMLC 監督 |

**審計要求**:

| 項目 | 規則 |
|------|------|
| 操作日誌 | 所有管理操作全程記錄 |
| 保留期限 | 最少 5 年 (MGA)、7 年 (財務) |
| 不可篡改 | Hash 鏈保護 |
| 即時存取 | 監管要求時 24 小時內提供 |

## 4. Functional Requirements — 代理 (Ch8)

### FR-AGT-01: 代理層級結構

**來源**: Ch8 §8.2

| 項目 | 規則 |
|------|------|
| 最大層級 | **10 層** |
| 信用額度分配 | 僅限由上而下 (上級 → 下級) |
| 每層額度 | 不可超過上級分配的額度 |
| 新代理建立 | 須上級代理或租戶管理員核准 |

**代理角色**:

| 角色 | 權限 | 說明 |
|------|------|------|
| 總代理 | 管理下線代理、分配額度、查看全線報表 | 租戶直屬 |
| 中間代理 | 管理下線、向下分配額度 | 可多層 |
| 末端代理 | 管理玩家、不可再分 | 直接面對玩家 |

### FR-AGT-02: 雙錢包模型

**來源**: Ch8 §8.3

| 錢包 | 說明 | 提款規則 |
|------|------|---------|
| **CASH** | 玩家自有現金 | 依 KYC 限額提款 |
| **CREDIT** | 代理授信額度 | 不可提款，僅用於投注 |

### FR-AGT-03: 信用額度管理

**來源**: Ch8 §8.3

| 項目 | 規則 |
|------|------|
| 初始額度 | 代理設定 (預設 0) |
| 額度調整 | 可隨時調高/調低，不可低於已使用額度 |
| 額度上限 | 受上級代理分配的總額限制 |
| 已使用額度 | `信用額度 - 可用額度` |
| 自我排除檢查 | 授信或調整前檢查玩家排除狀態 (**引用 Ch15 SSOT**) |
| 排除廣播 | 玩家觸發自我排除 → 自動凍結 CREDIT 錢包 + 通知代理 |

### FR-AGT-04: 信用風險閾值

**來源**: Ch8 §8.3

| 使用率 | 風險等級 | 處置 |
|--------|---------|------|
| ≤ 80% | 正常 | -- |
| 81-90% | 警告 | 通知代理 |
| 91-100% | 高風險 | 限制新投注，通知上級 |
| > 100% | 嚴重 | 凍結帳戶，強制結算 |

### FR-AGT-05: 信用額度併發控制

**來源**: Ch8 §8.5

| 項目 | 規則 |
|------|------|
| 鎖定策略 | 樂觀鎖 (version 欄位) — 適用於中低併發 |
| 高併發場景 | 同一玩家同時多筆投注 → 序列化額度扣減 (與 Ch2 §2.7 情境 B 一致) |
| 超額處理 | 併發導致瞬時超額 → 拒絕後續投注，不回滾已成功投注 |
| 額度刷新 | 投注結算 (Win/Loss) 後即時更新可用額度 |

### FR-AGT-06: 佣金模型 (4 種)

**來源**: Ch8 §8.4

| 模型 | 計算方式 | 適用場景 |
|------|---------|---------|
| **收益分成** | 淨盈虧 x 分成比例 (階梯式) | 最常見 |
| **流水返佣** | 有效投注額 x 返佣率 (按遊戲類型) | 大流水代理 |
| **CPA** | 每位新註冊/首存玩家固定金額 | 推廣期 |
| **混合模式** | 收益分成 + 流水返佣 | 大型代理 |

**收益分成階梯** (預設，DB 可配置):

| 月淨盈利 | 分成比例 |
|---------|---------|
| < $10,000 | 30% |
| $10,000-$50,000 | 35% |
| $50,000-$200,000 | 40% |
| > $200,000 | 45% |

**流水返佣率** (按遊戲類型，預設):

| 遊戲類型 | 返佣率 |
|---------|--------|
| Slots | 0.5% |
| Live Casino | 0.3% |
| Sports | 0.4% |
| Table Games | 0.2% |

### FR-AGT-07: 佔成模式 (Position Holding)

**來源**: Ch8 §8.4

| 項目 | 規則 |
|------|------|
| 概念 | 代理宣告承擔風險的百分比 |
| 盈利分配 | 玩家輸 → 代理獲得宣告比例的利潤 |
| 虧損承擔 | 玩家贏 → 代理承擔宣告比例的虧損 |
| 正規化 | 若下線佔成合計 > 100%，按比例縮減 |

### FR-AGT-08: 結算週期 + 負結轉

**來源**: Ch8 §8.5

**結算週期**:

| 週期 | 適用場景 | 結算日 |
|------|---------|--------|
| 每週 | 一般代理 | 每週一 |
| 每月 | 大型代理 / 特殊合約 | 每月 1 日 |

**結算流程**: 系統計算 → 財務審核 → 主管核准 (大額) → 自動發放

**負結轉規則**:

| 規則 | 說明 |
|------|------|
| 負餘額結轉 | 代理本期虧損結轉至下期 |
| 閾值重置 | 累計虧損達 -$1,000,000 時可申請重置 |
| 年度重置 | 年底可選擇性重置 (須審批) |
| 多幣種結轉 | 統一以代理結算幣種計算，月結時按結算日即時匯率折算 |
| FX 風險歸屬 | 代理承擔投注日至結算日之間匯率波動 (**引用 Ch2 §2.13 SSOT**) |
| 與信用額度關係 | 負結轉**不影響**信用額度計算。`可用信用 = 信用額度 - 已使用額度`（負結轉是佣金層面虧損，非信用層面債務） |

### FR-AGT-09: 大額結算審批門檻

**來源**: Ch8 §8.12 (v2.2 GAP-3，Ron 已確認預設值)

**審批層級**:

| 單筆結算金額 | 審批層級 | SLA |
|------------|---------|-----|
| < $10,000 | 自動發放 | 即時 |
| $10,000-$49,999 | Manager 審批 | 4 小時 |
| $50,000-$99,999 | CFO 審批 | 24 小時 |
| >= $100,000 | CFO + CEO 雙重審批 | 48 小時 |

**累計監控**:

| 指標 | 閾值 | 處理 |
|------|------|------|
| 單一代理月度累計結算 | >= $500,000 | 觸發升級審查 |
| 單一代理單週結算增長 | > 200% (vs 前 4 週均值) | FLAG + 人工審核 |
| 新代理首月結算 | >= $50,000 | 自動 FLAG |

**配置化**: 所有門檻值可按品牌/管轄區配置 (遵循 Ch0 §0.10 三層覆蓋)，門檻調整須 Maker-Checker 審批。

### FR-AGT-10: 代理帳戶安全

**來源**: Ch8 §8.11 (v2.2 GAP-2)

**認證要求**:

| 項目 | 規則 |
|------|------|
| MFA | 所有代理帳戶強制 TOTP 或硬體金鑰 |
| 首次登入 | 強制設定 MFA，未設定前禁止任何操作 |
| 備援 | 一次性恢復碼 (10 組) |

**IP 白名單**:

| 項目 | 規則 |
|------|------|
| IP 限制 | 僅可從預先註冊的 IP 登入 |
| 最大 IP 數 | 每帳戶 <= 5 個 |
| IP 變更 | 須上級代理或租戶管理員核准 |
| 非白名單 IP | 拒絕 + 通知帳戶持有人及上級代理 |

**Session 管理**:
- 閒置超時: 30 分鐘 → 自動登出
- 同一帳戶僅允許 1 個活躍 Session
- 重複登入: 新 Session 踢掉舊 Session + 通知

**登入失敗保護**:
- 連續 5 次失敗 → 鎖定 15 分鐘
- 連續 10 次失敗 → 鎖定 1 小時 + 通知上級
- 連續 20 次失敗 → 永久鎖定 + 須人工解鎖

**敏感操作再認證** (須重新輸入 MFA):
- 信用額度調整
- 結算審批
- 下線代理建立/停用
- 佣金模型變更 (+ 上級核准)
- 代理層級變更 (+ 租戶管理員核准)

### FR-AGT-11: 代理層級變更資料遷移

**來源**: Ch8 §8.6

| 場景 | 遷移規則 |
|------|---------|
| 代理上移 (升為上級) | 下線玩家與子代理跟隨遷移 |
| 代理下移 (降為下級) | 下線玩家保留，子代理需重新分配 |
| 代理轉移 (更換上級) | 下線玩家跟隨，佣金歷史保留在原代理報表 |
| 結算中轉移 | 當期結算完成後才生效 (不可在結算週期中途轉移) |
| 佣金歷史 | 永久保留在原代理下，不隨轉移而遷移 |
| 信用額度 | 轉移後由新上級重新分配 |

### FR-AGT-12: 代理自助門戶

**來源**: Ch8 §8.7

| 功能 | 說明 |
|------|------|
| 儀表板 | 即時佣金、下線統計、績效趨勢 |
| 玩家報表 | 下線玩家活動、盈虧、流水 |
| 佣金報表 | 歷史佣金、結算明細 |
| 下線管理 | 建立/停用下線代理 |
| 促銷工具 | 產生推廣連結、追蹤碼 |
| 信用管理 | 查看/調整下線額度 |

### FR-AGT-13: 代理風控

**來源**: Ch8 §8.8

| 風險 | 偵測方式 | 處置 |
|------|---------|------|
| 同 IP 玩家濫用 | IP 關聯分析 | 調查 + 可能凍結 |
| 佔成套利 | 上下線佔成不合理 | 人工審核 |
| 多帳戶連結 | 設備/支付方式關聯 | 與 Ch6 風控協同 |
| 異常佣金 | 佣金突增偏離歷史 | FLAG + 調查 |
