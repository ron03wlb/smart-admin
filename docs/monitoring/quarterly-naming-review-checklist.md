# 命名規範季度審查清單

**版本**: 1.0.0
**最後更新**: 2026-02-02
**維護團隊**: SmartAdmin Architecture Team
**審查週期**: 每季度最後一週（3月/6月/9月/12月）

---

## 📋 審查目的

確保 SmartAdmin 命名規範的持續執行和改進，通過定期審查機制：

1. **驗證合規性**: 確認所有代碼遵循單數命名標準
2. **評估工具效能**: 檢查自動化工具的有效性
3. **審查豁免清單**: 確保豁免項目仍然合理
4. **改進流程**: 識別並修正流程中的問題
5. **培訓需求**: 確定團隊培訓方向

---

## ✅ 季度審查清單

### 第一部分：命名規範合規性審查（必須）

**負責人**: 架構團隊負責人
**時間要求**: 2-3 小時

#### 1.1 Entity 表名檢查

- [ ] **運行 ArchUnit 測試**
  ```bash
  cd smart-admin-api-java21-springboot3
  ./gradlew :sa-admin:test --tests ArchitectureTest#tableNameMustBeSingular
  ```
  - 預期結果: ✅ 100% 通過，零違規
  - 如有失敗: 記錄違規詳情，創建 Issue

- [ ] **手動抽查 Entity 類**
  - 隨機抽查 10 個最近修改的 Entity 類
  - 驗證 `@TableName` 註解使用單數形式
  - 檢查是否有新的豁免需求

- [ ] **數據庫表名驗證**
  ```sql
  -- PostgreSQL: 查詢所有表名
  SELECT table_name
  FROM information_schema.tables
  WHERE table_schema = 'public'
    AND table_name LIKE 't_%'
  ORDER BY table_name;
  ```
  - 手動檢查是否有複數表名（除豁免清單外）
  - 對比 Entity 類和實際數據庫表名是否一致

#### 1.2 Package 命名檢查

- [ ] **驗證 Package 命名**
  ```bash
  # 查找可能的複數 package
  find . -type d -name "*users*" -o -name "*orders*" -o -name "*goods*"
  ```
  - 預期結果: 無複數 package 名稱
  - 特殊情況: `*.api.users.*` (API 路徑映射允許複數)

- [ ] **API 路徑命名檢查**
  ```bash
  # 檢查 Controller 中的 @RequestMapping
  grep -r "@RequestMapping" smart-admin-api-java21-springboot3/sa-admin/src/main/java \
    | grep -v "/api/v1/.*s/"
  ```
  - API 路徑應使用複數 (RESTful 標準)
  - 確認 API 複數路徑對應的是單數 Entity

#### 1.3 Mapper XML 命名檢查

- [ ] **批量檢查 Mapper.xml 表名**
  ```bash
  # 查找可能的複數表名引用
  grep -r "FROM t_.*s " smart-admin-api-java21-springboot3/sa-admin/src/main/resources/mapper
  ```
  - 排除豁免清單: `t_*_metrics`, `t_*_statistics`, `t_*_analytics`
  - 記錄任何發現的違規

## 🔧 審查工具與腳本

### 自動化審查腳本

創建 `scripts/quarterly-naming-review.sh`:

```bash
#!/bin/bash
# ====================================================================
# SmartAdmin 季度命名規範審查腳本
# ====================================================================
# 用途: 自動執行季度審查中的檢查項目
# 版本: 1.0.0
# ====================================================================

set -e

REPORT_DIR="docs/monitoring/reports"
REPORT_DATE=$(date +%Y-Q%q)
REPORT_FILE="$REPORT_DIR/naming-review-$REPORT_DATE.md"

mkdir -p "$REPORT_DIR"

echo "╔═══════════════════════════════════════════════════════════════╗"
echo "║  SmartAdmin 季度命名規範審查                                   ║"
echo "║  Report Date: $REPORT_DATE                                    ║"
echo "╚═══════════════════════════════════════════════════════════════╝"
echo ""

# ====================================================================
# 第一部分：ArchUnit 測試
# ====================================================================
echo "🔍 Part 1: 運行 ArchUnit 命名測試..."
cd smart-admin-api-java21-springboot3

if ./gradlew :sa-admin:test --tests ArchitectureTest#tableNameMustBeSingular --quiet; then
    echo "✅ ArchUnit 測試通過"
    archunit_result="PASS"
    violations_count=0
else
    echo "❌ ArchUnit 測試失敗"
    archunit_result="FAIL"
    violations_count=$(grep "violated" build/test-results/test/*.xml | wc -l || echo "0")
fi

cd ..

# ====================================================================
# 第二部分：統計 Entity 類數量
# ====================================================================
echo ""
echo "📊 Part 2: 統計 Entity 類數量..."
total_entities=$(find smart-admin-api-java21-springboot3 -name "*Entity.java" | wc -l)
echo "總 Entity 類數: $total_entities"

# ====================================================================
# 第三部分：檢查豁免數量
# ====================================================================
echo ""
echo "📋 Part 3: 檢查豁免清單..."
exemption_count=$(grep -c "保持複數" .agent/rules/foundation/01-naming-conventions.md || echo "0")
echo "當前豁免數量: $exemption_count (目標: ≤ 5)"

# ====================================================================
# 第四部分：檢查可能的複數 package
# ====================================================================
echo ""
echo "🔍 Part 4: 檢查 Package 命名..."
plural_packages=$(find smart-admin-api-java21-springboot3 -type d \
    -name "*users*" -o -name "*orders*" -o -name "*goods*" | wc -l || echo "0")
echo "發現可能的複數 package: $plural_packages"

# ====================================================================
# 第五部分：GitHub PR 統計（需要 gh CLI）
# ====================================================================
echo ""
echo "📈 Part 5: 統計 GitHub PR 數據..."
if command -v gh &> /dev/null; then
    # 計算季度起始日期（3 個月前）
    start_date=$(date -d "3 months ago" +%Y-%m-%d)

    total_prs=$(gh pr list --state all --search "created:>=$start_date" --json number | jq length)
    echo "本季度 PR 總數: $total_prs"
else
    echo "⚠️  gh CLI 未安裝，跳過 PR 統計"
    total_prs="N/A"
fi

# ====================================================================
# 生成報告
# ====================================================================
echo ""
echo "📝 生成審查報告..."

cat > "$REPORT_FILE" <<EOF
# 命名規範季度審查報告 - $REPORT_DATE

**生成日期**: $(date +%Y-%m-%d)
**審查週期**: $REPORT_DATE
**自動生成**: quarterly-naming-review.sh

---

## 📊 執行摘要

| 檢查項目 | 結果 |
|---------|------|
| ArchUnit 測試 | $archunit_result |
| 違規數量 | $violations_count |
| Entity 類總數 | $total_entities |
| 豁免數量 | $exemption_count (目標: ≤ 5) |
| 複數 Package | $plural_packages |
| 本季度 PR 總數 | $total_prs |

---

## ✅ 檢查清單

### Part 1: ArchUnit 測試
- **結果**: $archunit_result
- **違規數量**: $violations_count
- **目標**: 零違規

### Part 2: Entity 類統計
- **總數**: $total_entities
- **測試覆蓋率**: 計算中...

### Part 3: 豁免清單
- **當前數量**: $exemption_count
- **目標**: ≤ 5
- **評估**: $([ $exemption_count -le 5 ] && echo "✅ 達標" || echo "❌ 超標")

### Part 4: Package 命名
- **複數 Package 數量**: $plural_packages
- **目標**: 0（除 API 路徑映射外）

### Part 5: PR 統計
- **本季度 PR 總數**: $total_prs
- **需手動統計**:
  - 命名檢查觸發次數
  - PR 阻止率

---

- [ ] 識別問題並制定改進計劃
- [ ] 提交審查報告給技術經理審批

---

**下次審查**: $(date -d "+3 months" +%Y年%m月)

EOF

echo "✅ 報告已生成: $REPORT_FILE"
echo ""
echo "╔═══════════════════════════════════════════════════════════════╗"
echo "║  審查完成！                                                    ║"

echo "╚═══════════════════════════════════════════════════════════════╝"
```
