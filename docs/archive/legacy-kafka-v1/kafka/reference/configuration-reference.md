# Configuration Reference

Complete reference for all SmartAdmin Kafka configuration properties.

## Overview

SmartAdmin Kafka integration uses a combination of custom properties (`smart.kafka.*`) and standard Spring Kafka properties (`spring.kafka.*`).

**Configuration files**:
- `sa-base.yaml` - Environment-specific configurations
- `application.yml` - Default/common configurations
- Environment profiles: `dev`, `test`, `pre`, `prod`

**Property precedence**:
1. Environment variables (highest priority)
2. Profile-specific YAML files (`sa-base-{profile}.yaml`)
3. Default YAML files
4. Framework defaults (lowest priority)

---

## SmartAdmin Properties

### smart.kafka.enabled

Enable or disable Kafka integration.

**Type**: `Boolean`
**Default**: `false`
**Required**: Yes (must be explicitly set to `true`)

**Example**:
```yaml
smart:
  kafka:
    enabled: true  # Enable Kafka integration
```

**Behavior**:
- `true`: Kafka components are auto-configured and started
- `false`: Kafka beans are not created, no connection attempts

**Use cases**:
- Disable Kafka in local development
- Disable Kafka in certain test scenarios
- Feature toggle for gradual rollout

---

### smart.kafka.bootstrap-servers

Comma-separated list of Kafka broker addresses.

**Type**: `String`
**Default**: None
**Required**: Yes (when `enabled=true`)
**Format**: `host1:port1,host2:port2,host3:port3`

**Examples**:

**Development** (single broker):
```yaml
smart:
  kafka:
    bootstrap-servers: localhost:9092
```

**Test** (test cluster):
```yaml
smart:
  kafka:
    bootstrap-servers: kafka-test-1.internal:9092,kafka-test-2.internal:9092
```

**Production** (HA cluster):
```yaml
smart:
  kafka:
    bootstrap-servers: kafka-prod-1:9092,kafka-prod-2:9092,kafka-prod-3:9092
```

**Best practices**:
- List all brokers for redundancy
- Use DNS names (not IPs) for flexibility
- Minimum 3 brokers for production

## Spring Kafka Producer Properties

### spring.kafka.producer.acks

Number of acknowledgments the producer requires before considering a request complete.

**Type**: `String`
**Default**: `1`
**Recommended**: `all` (for production)
**Options**: `0`, `1`, `all` (or `-1`)

**Values**:
| Value | Behavior | Durability | Performance |
|-------|----------|------------|-------------|
| `0` | No acknowledgment | Lowest | Highest |
| `1` | Leader acknowledges | Medium | Medium |
| `all` | All replicas acknowledge | Highest | Lowest |

**Example**:
```yaml
spring:
  kafka:
    producer:
      acks: all  # Wait for all replicas (production)
```

**Use cases**:
- `all`: Critical data (orders, payments, transactions)
- `1`: Important data (notifications, logs)
- `0`: Metrics, analytics (loss acceptable)

---

### spring.kafka.producer.retries

Number of retries before giving up on sending a message.

**Type**: `Integer`
**Default**: `2147483647` (Integer.MAX_VALUE)
**Recommended**: `3` (for bounded retry)

**Example**:
```yaml
spring:
  kafka:
    producer:
      retries: 3  # Retry up to 3 times
      retry-backoff-ms: 100  # Wait 100ms between retries
```

**Related properties**:
- `retry-backoff-ms`: Delay between retries (default: 100ms)
- `delivery-timeout-ms`: Total time for retries (default: 120000ms)

---

### spring.kafka.producer.batch-size

Batch size in bytes for batching multiple records into a single request.

**Type**: `Integer`
**Default**: `16384` (16 KB)
**Recommended**: `16384` - `32768` (16-32 KB)

**Example**:
```yaml
spring:
  kafka:
    producer:
      batch-size: 16384  # 16 KB batches
      linger-ms: 10      # Wait 10ms to fill batch
```

**Performance tuning**:
- Larger batches → better throughput, higher latency
- Smaller batches → lower latency, lower throughput
- Balance with `linger-ms` for optimal batching

---

### spring.kafka.producer.linger-ms

Time to wait before sending a batch (allows batching more records).

**Type**: `Long`
**Default**: `0` (send immediately)
**Recommended**: `10` - `100` (for batching)

**Example**:
```yaml
spring:
  kafka:
    producer:
      linger-ms: 10  # Wait 10ms for more records
```

**Behavior**:
- `0`: Send immediately (lowest latency)
- `10`: Wait 10ms (good balance)
- `100`: Wait 100ms (maximum batching)

**Trade-off**:
- Higher linger → more batching → better throughput
- Lower linger → less batching → lower latency

---

### spring.kafka.producer.compression-type

Compression codec for all data generated by the producer.

**Type**: `String`
**Default**: `none`
**Recommended**: `lz4` or `snappy`
**Options**: `none`, `gzip`, `snappy`, `lz4`, `zstd`

**Example**:
```yaml
spring:
  kafka:
    producer:
      compression-type: lz4  # Fast compression
```

**Comparison**:
| Codec | Compression Ratio | Speed | CPU Usage | Use Case |
|-------|------------------|-------|-----------|----------|
| `none` | 1x | Fastest | Lowest | Low bandwidth cost |
| `lz4` | 2-3x | Very fast | Low | **Recommended** |
| `snappy` | 2-3x | Fast | Low | Google ecosystem |
| `gzip` | 3-5x | Slow | High | Storage-constrained |
| `zstd` | 3-4x | Medium | Medium | Kafka 2.1+ |

---

### spring.kafka.producer.enable-idempotence

Enable idempotent producer (exactly-once semantics within partition).

**Type**: `Boolean`
**Default**: `false`
**Recommended**: `true` (for production)

**Example**:
```yaml
spring:
  kafka:
    producer:
      enable-idempotence: true  # Prevent duplicate messages
```

**Behavior**:
- `true`: Producer assigns sequence numbers, broker deduplicates
- `false`: At-least-once delivery (duplicates possible)

**Automatic settings** (when `true`):
- `acks=all` (enforced)
- `retries=Integer.MAX_VALUE` (enforced)
- `max-in-flight-requests-per-connection=5` (enforced)

**Use case**: All production workloads (orders, payments, state changes)

---

### spring.kafka.producer.transaction-id-prefix

Prefix for transactional producer IDs (enables transactions).

**Type**: `String`
**Default**: None
**Required**: Only for transactional producers

**Example**:
```yaml
spring:
  kafka:
    producer:
      transaction-id-prefix: smart-admin-tx-  # Enables transactions
```

**Behavior**:
- If set: Enables transactional producer
- Each instance gets unique ID: `{prefix}{instanceId}`
- Enables exactly-once semantics across topics

**Use case**: Atomic multi-topic writes (order + payment messages)

---

## Spring Kafka Consumer Properties

### spring.kafka.consumer.group-id

Consumer group ID (logical subscriber to topics).

**Type**: `String`
**Default**: None
**Required**: Yes (for group management)

**Example**:
```yaml
spring:
  kafka:
    consumer:
      group-id: order-processor  # Default group ID
```

**Note**: Usually overridden per `@KafkaListener`:
```java
@KafkaListener(
    topics = "smart-admin-order",
    groupId = "order-processor"  # Per-listener group
)
```

**Best practices**:
- Use descriptive names: `{service}-{topic}-processor`
- One group per logical consumer
- Multiple instances in same group → load balancing

---

### spring.kafka.consumer.enable-auto-commit

Automatically commit offsets periodically.

**Type**: `Boolean`
**Default**: `true`
**Recommended**: `false` (for manual control)

**Example**:
```yaml
spring:
  kafka:
    consumer:
      enable-auto-commit: false  # Manual offset management
    listener:
      ack-mode: manual  # Required with false
```

**Behavior**:
- `true`: Offsets committed automatically every `auto-commit-interval-ms`
- `false`: Application must commit offsets manually

**Recommendation**: Always use `false` with `ack-mode: manual` for:
- Guaranteed processing before commit
- Transactional processing
- At-least-once delivery guarantees

---

### spring.kafka.consumer.auto-offset-reset

What to do when no initial offset or current offset does not exist.

**Type**: `String`
**Default**: `latest`
**Options**: `earliest`, `latest`, `none`

**Example**:
```yaml
spring:
  kafka:
    consumer:
      auto-offset-reset: earliest  # Read from beginning
```

**Behavior**:
| Value | Behavior | Use Case |
|-------|----------|----------|
| `earliest` | Read from beginning of topic | First-time consumers, reprocessing |
| `latest` | Read only new messages | Real-time processing |
| `none` | Throw exception if no offset | Strict offset management |

**Caution**: `earliest` on production can cause massive reprocessing!

---

### spring.kafka.consumer.max-poll-records

Maximum number of records returned in a single poll().

**Type**: `Integer`
**Default**: `500`
**Recommended**: `100` - `1000` (based on processing time)

**Example**:
```yaml
spring:
  kafka:
    consumer:
      max-poll-records: 500  # Fetch 500 records per poll
```

**Tuning**:
- Larger values → better throughput, more memory
- Smaller values → lower latency, less memory
- Must process all records within `max-poll-interval-ms`

**Rule of thumb**:
```
max-poll-records * avg_processing_time_per_record < max-poll-interval-ms
```

---

### spring.kafka.consumer.fetch-min-bytes

Minimum amount of data the server should return for a fetch request.

**Type**: `Integer`
**Default**: `1` (byte)
**Recommended**: `1024` - `10240` (1-10 KB for batching)

**Example**:
```yaml
spring:
  kafka:
    consumer:
      fetch-min-bytes: 1024       # Wait for 1 KB
      fetch-max-wait-ms: 500      # Or 500ms timeout
```

**Behavior**:
- Broker waits until `fetch-min-bytes` available OR `fetch-max-wait-ms` elapsed
- Reduces number of fetch requests
- Improves throughput for high-volume topics

---

### spring.kafka.consumer.max-poll-interval-ms

Maximum delay between poll() calls before consumer is considered dead.

**Type**: `Long`
**Default**: `300000` (5 minutes)
**Recommended**: `60000` - `300000` (1-5 minutes)

**Example**:
```yaml
spring:
  kafka:
    consumer:
      max-poll-interval-ms: 300000  # 5 minutes
```

**Critical**: Ensure processing time < max-poll-interval-ms:
```
batch_size * avg_processing_time < max-poll-interval-ms
```

**Symptom of violation**: Consumer rebalancing loops

## Spring Kafka Listener Properties

### spring.kafka.listener.ack-mode

Acknowledgment mode for committing offsets.

**Type**: `Enum`
**Default**: `BATCH`
**Recommended**: `MANUAL` (for control)
**Options**: `RECORD`, `BATCH`, `TIME`, `COUNT`, `COUNT_TIME`, `MANUAL`, `MANUAL_IMMEDIATE`

**Example**:
```yaml
spring:
  kafka:
    listener:
      ack-mode: MANUAL  # Manual offset commit
```

**Modes**:
| Mode | When Commits | Use Case |
|------|-------------|----------|
| `RECORD` | After each record | Slow but safe |
| `BATCH` | After poll batch | Default behavior |
| `MANUAL` | Application calls ack() | **Recommended** |
| `MANUAL_IMMEDIATE` | Immediately on ack() | Transactional |

**Usage with MANUAL**:
```java
@KafkaListener(topics = "smart-admin-order")
public void listen(ConsumerRecord<String, String> record, Acknowledgment ack) {
    processMessage(record);
    ack.acknowledge();  # Commit offset
}
```

---

### spring.kafka.listener.concurrency

Number of concurrent listener threads per topic.

**Type**: `Integer`
**Default**: `1`
**Recommended**: `3` - `10` (matches partition count)

**Example**:
```yaml
spring:
  kafka:
    listener:
      concurrency: 3  # 3 threads per listener
```

**Best practice**: Set concurrency = number of partitions:
- 3 partitions → concurrency: 3
- 6 partitions → concurrency: 6
- More threads than partitions → wasted threads

**Per-listener override**:
```java
@KafkaListener(
    topics = "smart-admin-order",
    concurrency = "5"  # Override default
)
```

---

### spring.kafka.listener.type

Container type for listeners.

**Type**: `Enum`
**Default**: `SINGLE`
**Options**: `SINGLE`, `BATCH`

**Example**:
```yaml
spring:
  kafka:
    listener:
      type: SINGLE  # Single-message listeners
```

**Modes**:
- `SINGLE`: `@KafkaListener` receives `ConsumerRecord<K, V>`
- `BATCH`: `@KafkaListener` receives `List<ConsumerRecord<K, V>>`

## Kafka Native Properties

### spring.kafka.properties.*

Any native Kafka property can be set under this prefix.

**Format**: `spring.kafka.properties.{kafka-property-name}`

**Examples**:

**Security (SSL)**:
```yaml
spring:
  kafka:
    properties:
      security.protocol: SSL
      ssl.truststore.location: file:/etc/kafka/truststore.jks
      ssl.truststore.password: ${TRUSTSTORE_PASSWORD}
      ssl.keystore.location: file:/etc/kafka/keystore.jks
      ssl.keystore.password: ${KEYSTORE_PASSWORD}
```

**Security (SASL)**:
```yaml
spring:
  kafka:
    properties:
      security.protocol: SASL_SSL
      sasl.mechanism: SCRAM-SHA-512
      sasl.jaas.config: |
        org.apache.kafka.common.security.scram.ScramLoginModule required
        username="${KAFKA_USERNAME}"
        password="${KAFKA_PASSWORD}";
```

**Connection tuning**:
```yaml
spring:
  kafka:
    properties:
      connections.max.idle.ms: 540000  # 9 minutes
      request.timeout.ms: 30000        # 30 seconds
      session.timeout.ms: 10000        # 10 seconds
      heartbeat.interval.ms: 3000      # 3 seconds
```

## Complete Configuration Examples

### Development Environment

**File**: `sa-admin/src/main/resources/dev/sa-base.yaml`

```yaml
smart:
  kafka:
    enabled: true
    bootstrap-servers: localhost:9092

spring:
  kafka:
    # Producer
    producer:
      acks: 1                          # Fast acks for dev
      retries: 0                       # No retries for dev
      batch-size: 16384
      linger-ms: 0                     # Send immediately
      compression-type: none           # No compression for dev
      enable-idempotence: false        # Disabled for speed

    # Consumer
    consumer:
      group-id: smart-admin-dev
      enable-auto-commit: false
      auto-offset-reset: earliest      # Reprocess for testing
      max-poll-records: 100            # Small batches for debugging
      fetch-min-bytes: 1
      fetch-max-wait-ms: 500

    # Listener
    listener:
      ack-mode: MANUAL
      concurrency: 1                   # Single thread for debugging
      type: SINGLE
```

## Configuration Best Practices

### 1. Externalize Credentials

**❌ Bad** (hardcoded):
```yaml
spring:
  kafka:
    bootstrap-servers: kafka-prod:9092  # Hardcoded!
```

**✅ Good** (externalized):
```yaml
spring:
  kafka:
    bootstrap-servers: ${KAFKA_BOOTSTRAP_SERVERS}  # Environment variable
```

---

### 2. Environment-Specific Profiles

Use separate YAML files per environment:
```
resources/
├── dev/sa-base.yaml      # Development config
├── test/sa-base.yaml     # Test config
└── prod/sa-base.yaml     # Production config
```

---

### 3. Reasonable Defaults

Set sensible defaults in `application.yml`:
```yaml
spring:
  kafka:
    producer:
      acks: all
      enable-idempotence: true
    consumer:
      enable-auto-commit: false
    listener:
      ack-mode: MANUAL
```

## Property Validation

### Required Properties Checklist

**Before deployment, verify**:
- [ ] `smart.kafka.enabled=true`
- [ ] `smart.kafka.bootstrap-servers` set
- [ ] `spring.kafka.producer.acks=all` (production)
- [ ] `spring.kafka.producer.enable-idempotence=true` (production)
- [ ] `spring.kafka.consumer.enable-auto-commit=false`
- [ ] `spring.kafka.listener.ack-mode=MANUAL`
- [ ] Credentials externalized (no hardcoded values)
- [ ] Security configured (SSL/SASL for production)
